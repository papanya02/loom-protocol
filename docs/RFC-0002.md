# RFC-0002: NEXUS 0.2 Identity-Aware Session Profile

- Status: Experimental
- Version: 0.2
- Compatibility: Not wire-compatible with 0.1

## 1. Cryptographic profile

Noise name: `Noise_XX_25519_ChaChaPoly_BLAKE2s`

Prologue: `NEXUS/0.2;identity-cert-v1;capability-v1`

The implementation delegates Noise operations to `snow`. NEXUS MUST NOT implement custom DH, AEAD, hashing or Noise state-machine logic.

## 2. Identity

Stable Peer ID is `nx2` followed by lowercase hexadecimal BLAKE3 of the domain string `NEXUS-Peer-ID-v2` concatenated with the 32-byte Ed25519 root public key.

The root key signs the domain-separated Noise-key certificate:
`NEXUS-NOISE-KEY-CERT-v1 || root_public_key || noise_static_public_key`.

The certificate is exchanged as encrypted JSON after the Noise handshake. Receivers MUST compare its Noise public key with the authenticated remote static key returned by Noise.

## 3. Trust

The prototype uses explicit peer pinning. A valid certificate alone does not imply that a peer is trusted. The expected Peer ID must be supplied by the operator through an independent trusted channel.

## 4. Capability negotiation

Both peers send encrypted offers. A capability is an exact pair of string identifier and integer version. The negotiated set is the exact intersection. The base capability `nexus/base@2` is mandatory.

Current capabilities:
- `nexus/base@2`
- `nexus/message@1`
- `nexus/ping@1`

## 5. Application envelope

Fields:
- `protocol`: `nexus/0.2`
- `message_id`: unsigned 64-bit integer
- `kind`: message type
- `stream_id`: unsigned 32-bit integer
- `payload`: JSON value

The current profile uses message ID 2 for the single data message and 3 for its ACK. This is a test profile, not a complete sequencing/replay protocol.

## 6. Framing

TCP records use a 16-bit big-endian length prefix. Zero-length records are invalid. Record allocation is bounded to 65,535 bytes.

## 7. Non-goals

This RFC does not specify DHT, routing between third-party peers, NAT traversal, QUIC, relay behavior, offline delivery, multi-stream multiplexing, migration or a global trust system.
